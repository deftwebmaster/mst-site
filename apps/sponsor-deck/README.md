# Sponsor Deck

A polished, mobile-first static PWA for sponsor and sponsee conversations. 72 original cards across honesty, willingness, character defects, humility, relationships, accountability, service, spirituality, and all 12 Steps. Includes follow-up questions, favorites, guided sessions, optional device-local notes, and JSON backup/restore.

**Independent. Not affiliated with or endorsed by Alcoholics Anonymous or AA World Services. No copyrighted AA literature or official Step text is reproduced.** Step cards are original conversation prompts, not a replacement for working the Steps with appropriate guidance.

## Deploy on GitHub Pages — no build required

### Add to the existing matt.st website

1. Unzip this download. In the repository that already serves `matt.st`, create `apps/sponsor-deck/` inside its published directory.
2. Copy the **contents** of the included `sponsor-deck` folder into that directory. `index.html`, `app.js`, `cards.js`, `styles.css`, `sw.js`, `manifest.webmanifest`, and `icons/` must stay together. Keep `.nojekyll` in the publishing root if your repository needs it.
3. Commit and push. Preserve your existing Pages deployment, custom domain, and `CNAME` file. This app needs no additional `CNAME`.
4. Open `https://matt.st/apps/sponsor-deck/` after the existing Pages deployment finishes. Include the trailing slash.
5. Visit once online and wait for “Ready for offline conversations.” Reload, then test offline.

If the existing site has its own service worker, make sure its navigation handling does not intercept this app’s subdirectory. Sponsor Deck’s worker is scoped only to its own folder. If your site is generated by a framework, copy these files into that framework’s static/public asset directory so the output keeps this same folder structure.

### Deploy as a standalone GitHub Pages repository

1. Create a GitHub repository, e.g. `sponsor-deck`.
2. Put the included app files at the **repository root**, not inside an extra nested folder. The repository must have `index.html` at its root.
3. Open the repository’s **Settings → Pages**.
4. Under **Build and deployment**, choose **Deploy from a branch**. Select `main` and `/(root)`, then Save. If your repo uses a different default branch, select that branch instead.
5. Wait for the deployment, then open the Pages URL shown in Settings, typically `https://YOUR-USERNAME.github.io/sponsor-deck/`.
6. Keep HTTPS enabled. Installability and offline service workers require HTTPS (or localhost during development).

All URLs are relative. There is no hard-coded hostname or root path, so both deployment options work without editing source files. See GitHub’s guide: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## Preview locally

Do not double-click `index.html`: a `file://` URL does not support service workers. From this app folder, run:

```sh
python3 -m http.server 8000
```

Open `http://localhost:8000/`. No package manager, database, account, or API key is needed. For testing at a subpath, serve the parent directory and visit the app’s folder URL instead.

## Use the app

- **The deck:** choose a topic or the whole deck, then draw. Every matching card is visited before the draw bag reshuffles. Immediate repeats are avoided at the boundary. Reloading starts a new draw bag.
- **The 12 Steps:** filter further to one Step. There are two original cards per Step.
- **Favorites:** star any card. Favorites persist in this browser when device storage is available.
- **Sessions:** choose 3, 5, 8, or 12 cards. When the selected topic has fewer cards, the session uses all available cards. Each session uses unique cards. Move forward to pass, or go back to revisit.
- **Private notes:** saving is off by default. Unchecked sessions stay in memory; notes disappear on ending the session or reloading/closing the page. Checked sessions save their cards, progress, and notes as you type. Resume a saved draft from Sessions or review a completed session.
- **Your space:** export a JSON backup, review and merge an import, find install instructions, or clear local data. Imports merge favorites and add sessions with new IDs. Existing sessions with matching IDs remain unchanged; they are never overwritten. A backup can contain up to 200 sessions, 12 cards per session, and 10,000 characters per note (3 MB file limit).

## Install and offline use

- **iPhone/iPad:** open the HTTPS site in Safari, tap Share, then Add to Home Screen. On some versions, select Open as Web App when offered.
- **Android:** use Chrome’s Install app/Add to Home screen option.
- **Desktop:** use the install option in a supporting browser. Your space shows an Install button when the browser makes the install prompt available.

After a successful first online visit, all app assets and the complete card library are cached. Drawing, favorites, sessions, notes, and backup files work offline. Browser support and install UI vary; the ordinary website works without installation. Private browsing and storage clearing can remove saved data or offline assets.

## Privacy and data

The app has no analytics, trackers, ads, accounts, external fonts, or backend. The host may keep ordinary access logs; the app does not transmit notes or favorites. All app assets are served from the same origin.

Browser storage is **not encrypted**. Anyone using the same browser profile may read saved data. Avoid identifying details. Save only what you want on the device, keep exported files private, and export before changing browsers, hosts, or devices. Exported JSON contains plain-text saved notes. Unchecked temporary sessions are never exported. No cloud synchronization or automatic backup is provided.

Data belongs to the exact origin and browser profile. A move from `github.io` to `matt.st`, or from a browser to an installed app on some devices, may use different storage; use export/import to transfer deliberately. Other same-origin website scripts can access localStorage. Do not host private notes alongside untrusted scripts.

When another tab changes data, the current tab stops writing stale state and asks you to export any work and reload. Keep one active editing tab for best results. Storage errors produce a persistent warning; export in-memory changes before closing if saving fails.

## Updating the app

1. Edit files and keep card IDs stable to preserve favorites and session references.
2. Change `VERSION` in `sw.js` whenever a shell asset changes. Add any new runtime assets to `ASSETS`.
3. Deploy all files together. The worker precaches the entire shell before an update becomes available.
4. Open the app. A “new version is ready” banner appears; tap **Reload now**. If an unsaved session has notes, the app asks before discarding them. Closing all tabs and reopening also updates it. Existing saved data is retained.

The cache name includes the service worker scope. Cache cleanup touches only this app’s own caches. Do not delete the old IDs from `cards.js` without a data migration. Schema version 1 backups are validated and HTML in imported notes is rendered as text.
